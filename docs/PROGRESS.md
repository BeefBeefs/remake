## Item generator decoded (exe 0x417550, sentence 24 and monster kills)
Found via the sentence jump table (0x4344f0, 76 entries; case 24 -> 0x431e9a -> 0x417550). Signature `(char, level, x, y, count, counters)`:
1. **Table.Tbd 30 row = drop level** (343 rows x 22): `[tries, chance %, 10 x (table-31 row, grade code)]`. tries 0 = one try per player (quest items); a try succeeds when `rand%100 <= chance`; then slot `rand%10` picks the table-31 row (-1 = nothing). Level 6 = 10 x Malse's Gem (Black Hammer, dlv 6), 23 = 10 x Syria's Spirit Stone (Stone Spike, dlv 23), 0/2/4/7/9... mix the consumables/Mine with random equipment windows; 16 = Mine only.
2. **Table 31 row** = `(category, -, -, id, mask)` fixed item (category = Item.Ibn section; 4:1 = Mine, 3:0 / 10000000 / 20000000 = Tablet/Capsule/Meat families), or with category -1 `(-1, max, min, -1, mask)` = random equipment whose power value v satisfies `min <= v <= max`. Rows 100-256 are the 154 windows.
3. **Grade code** (3 decimal digits): units = plain items (Item.Ibn field 2 absent/0), tens = grade 1 (magic), hundreds = grade 2 (rare); grade 3 (uniques) is always allowed. Codes seen: 111, 11, 1.
4. **Selection**: the three item lists (sections 0 weapon, 1 armor, 2 accessory) are filtered by grade and window; a list is chosen by its total weight, then the item by weight = **Item.Ibn field 4** (15000 plain, 10000 magic, 9000/8000 better, 1000 unique). The window value is field 36 for sections 0/1 (+0xc0 in the node; field 37 also fits) and field 25 for accessories (+0x90; 26 also fits). Not decoded: the `mask & col 4` test (node +0x88; not field 7 as armor would never pass).
The remake's `randomDrop` now follows this; monsters roll their own drop chance (`[659]`) first, then call it with `[660]`. Gold is NOT in this table (monsters/chests give it separately), which matches the earlier gold-scale finding.

- Call site 0x459690 builds a defender struct from the monster object: `[+0]=2`, `[+4]=monster+4`, `[+0xc]=monster+0xe8`, `[+0x10]=monster+0xf0`, `[+0x34]=monster+0xd8`. The attack info (arg 1) has `[+0]` attacker kind, `[+4]`, `[+0x10]` attack power, `[+0x18+4*i]` per-element modifiers.
- Player hitting a monster (key `(2<<16)|0`): `damage = power * v * T11[mod+10] / 100 - monster[+0xe8]`, where `v = 10 + rand%3` if attackinfo[+4]==1 else `9 + rand%3`, `mod = attackinfo[0x18 + 4*(elem^1)]` with `elem = monster[+0xd8]` (pair-swapped 1-based index) and T11 = Table.Tbd 11 (values 8..12, so 10 = neutral). With no modifier this is `power * (9..11)/10`, which the remake already uses.
- Monster `+0xe8` is a flat defence subtracted after scaling. I could NOT map it to an Mct field: the exe never addresses the param block at the file offsets (0xa38/0xa5c +), so the record is copied in pieces. HP = [654] and exp = [696] fit a linear copy (+0xd4, +0x17c), but a linear map would put +0xe8 at [659] (drop chance, 0..40), which cannot be a flat defence against hits of ~10, so the layout is not linear. Candidate fields: [657] (20..120, rises with tier) and [656] (constant 50). Not applied in the remake.
- Hit reaction (0x459857): `pct = dmg*100/maxHP` (cap 49), looked up in Table 25 row for the chance the target is staggered.
- Kill exp (0x4134a0): per-player damage share `dmg[player]*10/maxHP`, Table 14 percent, times `monster[+0x17c]`/100 added to the player's exp at `+0xe8`; so `+0xe8` is the player's exp, shared slot with the monster's defence only in the damage struct.

## Class change (decoded from the exe, replaces the guessed rule)
The level-up routine 0x412fb0 (continuation 0x41333b-0x413480) decides it; fields of the player object: +0x2c current class id (16 / 6 / 9 / 5), +0x30 the profession OFFERED on the Status screen ("Change Profession to ..."), +0x34 level.
- **Usage counters** (0x4135a3, run for every damaging hit of the hero): total at +0xc0, nine counters at +0xc4..+0xe4. Counter k = hits with a wielded weapon of arms class k (the weapon object's field +0x10 = Item.Ibn field 0, classes 0..7), counter 8 = spell hits (and weapon classes 8 / 9); bare-handed hits only raise the total. **All of it restarts at every level-up**, so only the hits of the last level count (the old guess accumulated forever).

## Touch controls and fullscreen (Android)
- `src/touch.ts`: DOM overlay shown on touch devices (coarse pointer or first touch; `?touch=1` forces it, `?touch=0` hides it). Left: virtual stick (drives WASD, 18 px dead zone). Right: ATK (hold = Shift + left button aimed by `GameScene.touchAim`: nearest living enemy within 450 px, else 70 px in front of the hero), MAGIC (right button at the same aim, casts the spell selected in the HUD bar), RUN (R), DOG (Space), belt 1-4. Top: ITEM / STAT (C) / MAGIC (M) / MAP / QUEST / HELP / MENU (Esc) and FULL (fullscreen toggle; tries a landscape orientation lock, which Chrome only allows in fullscreen).
- Touching the game screen itself acts as the mouse (`App`: touchstart = press + click, drag moves the pointer, release lets go), so hold-to-walk, tap-to-attack, tapping NPCs / items / windows / the HUD spell bar and dialog advance work as with a mouse. Multi-touch: stick, buttons and the screen use separate pointers.
- `index.html` / `play.html` got a viewport meta (no zoom). Test: `touch.mjs` (emulated touch: stick moves the hero, ATK holds Shift+button, ITEM toggles the window, tap maps to the canvas, fullscreen on / off).
- Not covered: right-click-only extras (Tab + right click dog dash), two-finger gestures, text entry for the character name uses the on-screen keyboard only if the browser raises it for the canvas (untested on a real phone).
- Name entry on phones: tapping the name field (new-character screen, `SelectScene.wantsTextAt`) focuses a hidden `<input>` in `App` (inside the touch gesture, which browsers require to raise the keyboard); its `input` events become `Input.typed` characters / Backspace, Enter closes it.
